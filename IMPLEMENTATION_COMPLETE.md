## Как тестировать MVP

### Шаг 1: Создать турнир
Откройте http://localhost:5173/
- Введите название турнира
- Нажмите "Create Tournament"
- Вы получите ссылки на Admin и Display

### Шаг 2: Открыть две вкладки
1. **Admin**: http://localhost:5173/admin/{id}
2. **Display**: http://localhost:5173/display/{id}

### Шаг 3: Полный сценарий MVP

**Display Tab:** Откройте Display в отдельной вкладке/окне

**Admin Tab:**
1. Нажмите **START** → Display показывает таймер 15:00 (900 сек)
2. Наблюдайте, как таймер отсчитывает каждую секунду
3. Нажмите **PAUSE** → таймер остановился на определённом времени
4. Нажмите **RESUME** → таймер продолжает отсчёт с того же времени
5. Нажмите **NEXT LEVEL** → Display показывает новые блайнды (50/100) и полный таймер
6. Откройте Display в новой вкладке (или перезагрузите) → состояние восстановлено
7. Дождитесь конца уровня → сервер автоматически переключит на следующий уровень

**Ожидаемые результаты:**
- ✅ Таймер синхронизирован между админом и дисплеем
- ✅ Pause сохраняет точное время
- ✅ Resume продолжает с того же времени
- ✅ Next Level мгновенно обновляет дисплей
- ✅ Reload страницы восстанавливает текущее состояние

## Архитектура

### Backend структура
```
Tournament Engine
    ↓
Tournament Service (бизнес-логика)
    ↓
Tournament Repository (хранилище)
    ↓
REST API + WebSocket Gateway
```

### Frontend структура
```
Display/Admin Page
    ↓
Custom Hooks (useTournament, useRealtimeTournament)
    ↓
API Client (fetch + WebSocket)
    ↓
Server State
```

### Ключевые моменты

1. **Server-authoritative**: Сервер — источник истины
2. **Timer independent**: Вычисляется из серверного времени, не от `setInterval()`
3. **Pause/Resume**: Сохраняет оставшееся время корректно
4. **WebSocket broadcasts**: Каждую секунду отправляет обновления
5. **Graceful reconnect**: Новый клиент получает актуальное состояние
